# _vault — base de conhecimento do artigo

Notas de trabalho sobre o artigo de scheduling probabilístico e análise de risco
(`../paper/`). Não é documentação do código — é o raciocínio sobre **como publicar**,
para não se perder entre uma sessão e outra.

| Nota | O que tem |
|---|---|
| [Caminho para publicação](caminho-para-publicacao.md) | Por que o artigo hoje não seria aceito, qual pergunta de pesquisa ele deve responder, e o desenho com dado sintético. **Comece por aqui.** |
| [Diagnóstico técnico](diagnostico-tecnico.md) | Bugs verificados no código, gargalo de escalabilidade, e a lista de pendências do manuscrito e do repositório. |

## Convenção

- Um assunto por arquivo, nome em kebab-case, links relativos em Markdown (funcionam no
  GitHub e no VSCode).
- Cabeçalho com `status` e `atualizado` em cada nota.
- Notas de **diagnóstico** são fotos de um momento: se o código mudar, a nota fica velha e
  precisa ser revisitada. Notas de **estratégia** são vivas.
